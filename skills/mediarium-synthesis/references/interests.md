# 收藏、兴趣档案与个人发现

把兴趣档案当作可核对的阅读观察。收藏说明文章值得保留，原因可能是喜欢、研究、待核实、反对或稍后读；不能从收藏直接推出赞同、身份、敏感属性或人格结论。

## 何时读取和更新

- 新闻整合需要个性化时，先用本轮明确偏好和用户已有档案。已有档案可由用户提供路径；本机默认位置为 `$CODEX_HOME/skill-data/mediarium-synthesis/interest-profile.md`，未设置 `CODEX_HOME` 时为 `~/.codex/skill-data/mediarium-synthesis/interest-profile.md`。
- 普通简报不自动重写档案。用户要求“建立／更新兴趣档案”时才把分析作为持久资料保存到指定路径或上述独立数据目录，并告知位置。先读取已有内容，保留用户自己的说明和修正；不要覆盖用户维护的其他材料。
- 若环境不支持文件持久化，交付一份可保存的档案草案，并说明没有跨聊天保存。不声称已写入记忆或已完成同步。若写入被权限阻止，保留完整草案并按宿主权限流程处理。
- 个人档案不放进 skill 源码、共享技能包或公共仓库；不把兴趣档案写进 Codex 的 memories 目录、其他记忆服务或外部账户。

## 检视收藏

1. 首次建档不强加新闻的最近 72 小时限制。用 `search_articles({starred: true, status: "any", limit: 50})` 检查当前可见收藏总数和列表。若可获取完整索引，扫描全部标题，再选有代表性的正文；索引扫描不等于全部精读。
2. 全库收藏截断时，先列订阅，按源请求收藏并去重，依照取数说明识别剩余缺口。没有取全时把档案标成“基于部分收藏的初步观察”，不宣称概括所有收藏。
3. 兼顾不同日期、类别和来源。读代表文章确认其真正问题与角度，不凭标题下结论；同一事件的多篇收藏不等于多份长期兴趣证据。
4. 工具不返回收藏时间。发布日期只能表明文章年代，不能推出“最近才开始喜欢”或收藏顺序；做增量更新时对比文章 ID，并定期核对移除的收藏。无法核对全部收藏时，不声称已完成增量同步。

## 归纳方式

优先记录对选文有实际作用的内容：

- **主题与问题**：持续关心什么，以及关注它的哪些方面。
- **阅读角度**：偏向经验叙事、制度分析、文化现象、文本细读或其他实际可见角度。
- **表达和深度**：有正文支持时，记录偏好的论证密度、写作方式与篇幅。
- **阶段性关注**：集中于某事件的收藏先标成阶段线索；时间证据充分才谈持续性。

每个观察附代表文章 ID、标题、原文链接及文章日期，说明“文章实际呈现的内容”和“对用户兴趣的推测”之间的区别。使用“用户明确表示”“多篇材料支持的暂定观察”“单篇线索”这样的证据等级，不给没有统计基础的百分比。

优先采用用户明确的解释。用户说“只是工作资料”“这篇是反例”时，修正相应判断，保留简短更正说明，不继续把它当偏好。取消收藏不自动等于不喜欢，也不据此删去用户明确确认的兴趣。

## 档案建议格式

按材料多少调整，不需要空栏目或固定条目数。可采用以下结构：

```markdown
# 灵媒兴趣档案

更新日期：实际日期与用户时区
材料范围：实际检视的收藏范围、数量、正文读取程度和缺口

## 用户明确说明
记录用户原意及日期，优先于模型推测。

## 兴趣观察
### 某个主题或阅读角度
- 观察：用可修正的语言说明。
- 依据：文章 ID、标题、日期、原文链接；说明正文支持点。
- 证据程度：明确说明／多篇暂定观察／单篇线索。
- 时间性质：持续性有依据／阶段性／尚不能判断。
- 对选文的帮助：哪些内容可能值得推荐，不能据此推出什么。

## 更正与待确认
保留实际发生的纠正和重要不确定处；没有则省略。
```

## 用于推荐

把新闻的公共重要性和用户兴趣分开考虑。兴趣影响“小事精选”和阅读入口，不把不合既有口味的大事删掉，也不为迎合偏好曲解事实。

推荐时用具体理由，例如“这篇从民俗实践解释商业化，与收藏中反复出现的文化消费问题有关”，而非“你肯定喜欢”。保留少量跳出既有主题、但有独特价值的发现；无需设定机械比例。

无档案或证据不足时，可以依据本轮明确兴趣推荐，或把文章称为“值得留意的小事”，不要装作已了解用户长期口味。
