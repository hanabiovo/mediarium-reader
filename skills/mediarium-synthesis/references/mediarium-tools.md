# 灵媒取数说明

以下是 2026-11-03 在此项目源码与已连接工具中核实的能力。每次使用仍以运行环境的工具声明为准；如新增分页、分类检索、时间戳等参数，优先使用新能力。本文件描述已知接口，不要求修改服务。

## 定位已连接工具

灵媒通常显示为“灵媒／报刊亭”。已测试环境的工具前缀为 `mcp__codex_apps__app_`，接收者环境的前缀可能不同，按服务说明和下面的功能识别，不把同名的其他服务当成灵媒。便携分享版需要接收者自己连接灵媒，未绑定分享者环境中的依赖别名，也不携带任何接入令牌或服务器地址。直接使用本机已连接的灵媒工具；未连接时说明缺少灵媒接入，不用本地源码冒充实时数据。

| 工具 | 已核实参数 | 用途和限制 |
| --- | --- | --- |
| `list_subscriptions` | `category?`、`feed_id?`、`stats?` | 返回类别 → 报刊 → 栏目；类别名严格匹配，未命中时先列类别核对。`stats:true` 必须同时限定类别或源 |
| `search_articles` | `days?`、`feed_id?`、`limit?`、`query?`、`status?`、`starred?` | 返回总数、文章 ID、标题、来源、日期、已读状态和收藏标记；当前没有类别、分页、排序或时间上界参数 |
| `get_article` | `id`、`section?` | 返回 Markdown 正文、原文链接等；长文章会分节，第一次不一定返回全文；只读，不改变已读状态 |

`search_articles` 的 `status` 为 `any`、`unread` 或 `read`，默认 `any`。当前实现的 `any` 包含已读和未读，不包含已划掉的条目，不把它说成全库存。`limit` 默认 15、最多 50；设置更大的数也不会多取。`days` 是从请求时刻倒推发布时段，可用 1／2／3 分别表达最近 24／48／72 小时；当前无固定起止时间窗口，旧日期区间可能无法完整表达。索引的可见日期只有“日”，不能凭它补出具体发布时间。`starred:true` 按文章发布时间排序，并不返回收藏时间。

## 按类别收集索引

例如用户要求新闻类别近 48 小时复盘：

1. `list_subscriptions({category: "新闻"})` 得到实际源 ID。
2. 对每个源调用 `search_articles({feed_id: 源ID, days: 2, status: "any", limit: 50})`。
3. 按文章 ID 合并结果，记下每源的总数、已返回数、缺口和失败；同一本报刊的多个栏目也要分别检查。
4. 对选中的候选调用 `get_article({id: 文章ID})`，从正文和原文链接核实关键事实。

不要先全库取最新 50 篇再筛类别，这会让高产源挤掉其他来源。独立源的请求可以适量并行；对结果有依赖的正文读取和事件归并按需要继续。

## 截断、时间范围与停止条件

- 返回“共 N 篇，列出 M 篇”且 N > M 就是截断；只返回了 50 篇时，重复同一个请求不会得到下一页。
- 全库查询若截断，可改成按源收集。单源 `any` 截断时，可以分别请求 `read` 和 `unread`：只有两组都未截断，才能据此认为该源这两种状态的索引取全；合并后按 ID 去重。统计基于查询时的快照，阅读状态在过程中变化时不要强行对齐总数。
- 单组仍截断且接口没有分页时，保留明确的覆盖缺口，完成可见材料的整合。关键词检索可补某条主线，但不能证明整体完整；把 3 天依次改成 2 天、1 天只会取重叠的新文章，不能补回旧段。
- 不为取全而无限重试，不默默缩短用户要求的时段。失败请求最多作一次有理由的重试，仍失败则记录并继续其他材料。
- 多次请求以各自服务器当前时刻计算下界，期间也可能新增文章。报告本次目标窗口与截至时间，避免声称精确固定快照；请求跨度长时说明实际读取时段。
- 未读积压模式先看全库未读的总数和近期可见日期，再按所选类别各源展开。若索引截断，尤其不能把返回页最老日期当成积压起点。可以先整理可见近期部分，并交代更早未读未完整覆盖。
- 接口不支持的旧日期区间或完整历史，说明当前可完成的范围。不要虚构 `offset`、`cursor`、`published_before`、批量正文等参数。

## 覆盖记录

工作中可用紧凑表记录：源／请求范围／总数／返回数／是否截断／正文已读篇数／错误。最终面向用户缩成一两句话，数字必须来自实际调用；无法计算全类别总数时，报告已知源的情况，不补一个估算总数。

正文分为“已完整读取”“已读相关节／仅摘要”“仅扫描索引”三种状态即可。数百条索引不要求全部正文塞进上下文；核心事件的关键变化必须有正文依据。代表报道之外的标题线索不能承担未经核实的事实结论。
